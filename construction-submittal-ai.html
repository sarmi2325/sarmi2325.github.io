Construction Submittal Compliance AI.

From project specifications to vendor submittals — an AI system that extracts requirements, evaluates submitted products against them, and prepares compliance results for human review.

Role: AI Engineer — backend AI pipeline, reliability & evaluation
Team: Contributed as one of a larger engineering team  ·  Industry: Construction / Enterprise AI

The problem

On large commercial construction projects, every product that gets installed has to be checked against the project's written specifications before it can be approved. Suppliers submit hundreds to thousands of product data sheets per project, and a reviewer has to confirm each one meets the specified requirements. Done by hand, this is slow, inconsistent between reviewers, and a frequent source of rework and schedule risk.

How it works

An event-driven document-intelligence pipeline that keeps a human reviewer in control of the final decision.

Spec & product PDFs→ LLM extraction · requirements→ Vector retrieval · pgvector→ LLM matching · product ↔ spec→ Compliance verdict→ Reviewer routing→ Human review

Large projects process asynchronously in the background; approved products compile into a single reviewable package.

Requirement vs submittal

The core of the system: each requirement from the specification is checked against the submitted product's data, and every result stays reviewable.

What I did

  • Deterministic extraction. Made requirement extraction reproducible so the same document yields the same requirement set on re-run — stabilizing every downstream verdict.
  • Distributed-systems correctness. Traced and fixed a recurring class of silent event-ordering bugs where events were published before their database transaction committed, by enforcing commit-before-publish.
  • No more stalls. Made the retry / failure cap effective, added completion guarantees so no item silently disappears, and a scheduled reconciler to recover stuck work.
  • Routing. Implemented business-unit routing of items to the correct reviewer, with notification deduplication.
  • Evaluation & triage. Built parity and validation harnesses against known-good historical jobs, and triage tooling that labels each finding as a data-quality issue versus a real code/pipeline bug.

I worked on the backend AI pipeline — its reliability, correctness and evaluation — as part of a larger team that also owned the frontend, core infrastructure and other pipeline components.

Results

  • Materially reduced verdict inconsistency on re-runs by removing non-determinism from extraction.
  • Eliminated a class of silent failures where items were stranded with no retry.
  • Removed indefinite pipeline stalls via an effective failure cap and a reconciler.
  • Cut debugging time by separating data-quality issues from genuine code defects at triage.
  • Enabled reliable processing of projects with hundreds to thousands of line items.
